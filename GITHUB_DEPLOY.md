# Опубликовать Lingua Bridge Family в интернете

## 1. Загрузить проект на GitHub

1. Скачайте и распакуйте `lingua-bridge-family.zip`.
2. Установите Git for Windows: https://git-scm.com/download/win (если он ещё не установлен).
3. Откройте https://github.com/new и создайте новый **пустой** репозиторий с названием `lingua-bridge-family`. Не добавляйте README, `.gitignore` и лицензию при создании — они уже входят в папку проекта.
4. В распакованной папке проекта щёлкните правой кнопкой мыши по пустому месту и выберите «Открыть в терминале» / PowerShell.
5. Запустите скрипт:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\publish-to-github.ps1
```

6. Вставьте HTTPS URL созданного репозитория. Он выглядит как `https://github.com/ВАШ-ЛОГИН/lingua-bridge-family.git`.
7. Если Git попросит авторизацию, завершите вход в GitHub в открывшемся окне/по инструкции Git Credential Manager. Не передавайте пароль или токен посторонним.

Скрипт загружает файлы проекта, но не включает `.env`, секреты, локальные заявки и пользовательские отзывы.

## 2. Опубликовать сайт с сервером

1. Откройте https://dashboard.render.com/ и зарегистрируйтесь или войдите.
2. Нажмите **New + → Blueprint** и подключите свой GitHub-репозиторий `lingua-bridge-family`.
3. Render прочитает `render.yaml`. Проверьте настройку и создайте сервис.
4. После deploy, если у тебя уже есть API-ключ и ты хочешь включить ИИ, открой настройки сервиса → **Environment** → **Add Environment Variable** и добавь `OPENAI_API_KEY` со значением ключа. Если ключа пока нет, пропусти шаг: сайт и остальные разделы будут доступны, а чат сообщит, что ИИ не подключён.
5. После успешного deploy откройте ссылку `*.onrender.com` в панели Render.
6. Откройте `/admin.html` и войдите с секретом `ADMIN_TOKEN`, который Render сгенерировал в настройках сервиса (Environment). Не публикуйте его и не вставляйте в публичные сообщения.

Render YAML создаёт бесплатный веб-сервис для знакомства с проектом. На бесплатном плане сервис засыпает после периода бездействия, а файлы на диске не являются постоянным хранилищем: заявки и отзывы могут исчезнуть после перезапуска/засыпания или нового deploy. Не используйте такую конфигурацию для настоящего сбора персональных данных без подключения постоянной базы данных и публикации политики обработки персональных данных.

## Важно

- GitHub Pages не выполняет `server.js`. Чтобы работали API-запросы, ИИ, отзывы и заявки, нужен серверный хостинг (например, Render Web Service).
- `.env` и ключ `OPENAI_API_KEY` нельзя добавлять в GitHub. Храните их только в секретных настройках хостинга.
- После изменения файлов обновите репозиторий и выполните `git push`. Render автоматически запустит новый deploy.
